## 1. `topic_scan.py` — 选题扫描一键跑

把机械活全做掉：抓 11 个信源 RSS → AI 关键词过滤 → **按实体自动聚类** → 输出 Top N 候选簇 → 搜索需求验证 → 归档 markdown。

```bash
python3 tools/topic_scan.py --hours 48 --top 12
```

| 参数 | 说明 |
|---|---|
| `--hours N` | 时间窗，默认 48 |
| `--top N` | 输出前 N 个簇 |
| `--demand "词1" "词2"` | 对指定核心词跑搜索需求验证 |
| `--topic "名称\|kw1,kw2"` | 盯住某个簇，列出它命中的全部线索（含 URL） |
| `--from topic-scans/xxx.json` | 复用已有扫描结果，不重新抓源 |
| `--quiet` | 只打汇总，不列簇内标题 |

**输出样例**

```
📡 线索 87 条｜25 个候选簇｜原始：topic-scans/2026-09-23-1912.json
   ⚠️ 抓取失败：VentureBeat(HTTPError)、机器之心、HuggingFace Papers(HTTPError)

▸ OpenAI（12 条）
   · [TechCrunch] OpenAI launches GPT-6 Sol and Luna, boasting lower cost…
▸ 阿里（5 条）
   · [IT之家] 阿里千问发布 Qwen-Audio-3.1 系列语音大模型，并下调全线产品价格

🔎 搜索需求验证：
   ▸ GPT-6：3/3｜gpt-6 agi、gpt-6 release date、gpt-6 价格
```

**注意两点**
1. 脚本只做机械活。**"哪三件事值得写"仍然是判断**，聚类结果只是候选。
2. 无网络时搜索验证显示「⚠️ 联网失败」——**那不是"没有搜索需求"**，别当 0 分用（脚本刻意区分了这两种情况）。

## 2. `draft_kit.py` — 写稿提速

| 子命令 | 替代了什么手工动作 |
|---|---|
| `brief` | 逐个读风格卡 / 账号状态 / module-log，再逐条抄禁用词与规格 |
| `check <稿>` | 分别跑 preflight 与 voice_check，再把两边输出拼起来 |
| `handoff <稿>` | 通读全文挑核心数字、回忆每个数字指什么 |

```bash
python3 tools/draft_kit.py brief
python3 tools/draft_kit.py check topics/草稿-xxx.md
python3 tools/draft_kit.py handoff topics/草稿-xxx.md --append
```

`brief` 会**主动报账号状态是否过期**：

```
【账号状态】更新于 2026-09-12　⚠️ 已 11 天未更新，引用粉丝/收入前先让用户更新
【风格卡硬约束】1.术语先翻译成人话 2.去掉赘词 3.段落可长可短
【近 5 篇已用写法】…累计已用 14 条短语（脚本会自动查）
【写作规格】字数 1200–1800｜单段 ≤65 字｜禁用词 8 个…
```

`check` 把 27 项自检压成 FAIL/WARN 清单 + 文风偏差项，退出码跟随 preflight。

`handoff` 抽出「值得做成图/大字的数字」，并附原始上下文帮你回忆每个数字指什么：

```
| 数字 | 含义 | 出处 |
| 300 万 |  |  |
| 67.8%  |  |  |

   原始上下文：300 万 ← 一天跑约 300 万个沙盒，峰值同时有 38 万个在跑
```

> 它会先剔除 URL、arXiv 编号、日期、年份——这些含数字但不是"核心数字"。

## 3. `make_figs.py` — 配图模板

五类版式，统一冷灰科技蓝 `#3D5A80`、1080px 宽、每张自带标题与来源行。

```bash
python3 tools/make_figs.py <版式> -t "标题" -s "来源：XXX" -o assets/xx.png [数据参数]
```

| 版式 | 数据参数 | 适用 |
|---|---|---|
| `信息` | `-k "键::值"` | 论文 / 公告基本信息卡 |
| `对照` | `-c "头::副::主体::标签::备注"`（2–4 列） | 方案、路线对比 |
| `清单` | `-i "主::副"`（自动编号） | 案例、事故、要点罗列 |
| `条目` | `-i "左::主::右"`（不编号） | 法案编号、榜单这类左对齐列表 |
| `柱状` | `-d "标签:值:副标签"` ＋ `--unit %` / `--highlight-below N` | 数字对比 |

**完整示例**

```bash
# 对照卡
python3 tools/make_figs.py 对照 -t "同一天，两种手段" -s "2026-09-21" -o assets/ab.png \
  -c "加州::州长纽森::签 7 项法案::改规则::成本自己承担" \
  -c "得州::州长阿博特::停发许可::关闸门::审计没完先不开工"

# 柱状图（低于 7 的标橙）
python3 tools/make_figs.py 柱状 -t "镜像读取比例" -s "来源：论文 Table 3" -o assets/c.png \
  -d "Go:13.3:4.1GB" -d "Java:9.2:12.1GB" -d "Python:6.0:6.0GB" \
  --unit "%" --highlight-below 7 --baseline-label "实际被读取的数据占镜像的比例"
```

分隔符：列内字段用 `::`，柱状数据用 `:`（三段为 `标签:值:副标签`）。

**生成后一定要看一眼图**，确认没有文字溢出卡片边界、装饰元素没压到标题。
换平台要改脚本顶部的字体路径（`FONT_BOLD` / `FONT_REG` / `FONT_LAT`）。

## 4. `preflight.py` — 发布前自检（27 项）

只读、离线、确定性：同一份稿永远给同一个结果，不依赖模型自觉。

```bash
python3 tools/preflight.py formatted/xx-排版稿.md      # 退出码 0 = 可发布
python3 tools/preflight.py formatted/xx-排版稿.md --json
```

覆盖：禁用词｜**风格卡·自称与套话**｜标题规范｜核心判断开篇｜V6 六模块｜存疑表述｜
引用标记残留｜字数（1200–1800）｜占位符｜亲历式表述｜拼盘信号｜单段超长（≤65 字）｜
加粗密度（≤8%）｜小标题间距（≤600 字）｜配图数量｜分隔符混用｜感叹号｜序号泄漏｜
素材状态声明｜双源信号｜时间词新鲜度｜**同质化**（查 `module-log.md` 最近 5 篇）｜过渡钩子。

> 卡不到的部分（标题是否已说完、判断是否有增量、是否语义拼盘、事实是否核过）由人工过，脚本不假装检查过。

## 5. `wx_publish.py` — 一键发布

**前置条件**：`preflight` 退出码 0（脚本内置，不通过直接中止）。

```bash
python3 tools/wx_publish.py formatted/xx-排版稿.md --tag 深度解读
python3 tools/wx_publish.py formatted/xx-排版稿.md --dry-run          # 只跑本地三步，不联网
python3 tools/wx_publish.py formatted/xx-排版稿.md --replace <media_id>  # 重推，不留重复草稿
```

内部按顺序做完 9 件事：preflight → md2wx 渲染 → PIL 自画封面 → 字符级核验 →
取 token → 上传封面与配图（换永久 URL）→ 推草稿 → **若带 `--replace`，新稿上手后再删旧稿** → 回查 → 写日志。

输出压到 10 行：

```
① preflight ✅ PASS 24 · WARN 2 · FAIL 0
② 渲染 ✅ xx.html（25194 字符）
③ 封面 ✅ cover_xx.png（900×383，2 行标题）
④ 字符核验 ✅ 中文/字母数字/emoji 三段一致
⑤ token ✅（有效期 7200 秒）
⑥ 素材 ✅ 封面 1 张 + 配图 5 张（本地路径零残留）
⑦ 推草稿 ✅ media_id=guWaxy5UgiXI…
⑧ 回查 ✅ 标题「…」｜正文图 5 张｜本地残留 0 处
⑨ 日志 ✅ ~/.workbuddy/memory/2026-09-23.md
```

**凭据与错误处理**：从 `~/.workbuddy/.env` 读 `WX_APPID` / `WX_APPSECRET`，**不打印不回显**。
`40164` → 出口 IP 不在白名单（换 secret 无用）；`40125` → AppSecret 失效，需要新值。

> ⚠️ 一个高频坑：微信 `draft/add` **成功时不返回 `errcode`**，直接返回 `media_id`。
> 判断成功要用 `'media_id' in resp`，写成 `errcode == 0` 会把成功误报成失败。

## 6. `search_demand.py` — 搜索需求验证

微信搜一搜下拉词是金标准但拿不到，用 Bing / Google / 百度 的公开建议接口做替代验证。

```bash
python3 tools/search_demand.py "Agent 沙盒"
python3 tools/search_demand.py "GPT-6" --json
```

评分口径：**≥2 个具体长尾词 = 3 分**（用户在搜具体问题）｜只有泛核心词 = 1–2 分｜三引擎都无建议 = 0 分。

⚠️ **长尾词要看意图，不能只看分数**。例：搜"端侧AI"返回的是"端侧aiETF / 端侧ai十大龙头股"——那是股票词，不是需求；搜"AI 安全评估"返回"用 AI 写安全评价报告"——那是用 AI 做事，不是评估 AI。这两种都要人工重判。

## 7. `voice_check.py` — 文风体检

从你的真实语料建基线，再拿稿件逐项对照。

```bash
# 建基线（3–5 段你自己的文字放进 voice/语料/）
python3 tools/voice_check.py --corpus voice/语料 --save voice/基线.json

# 体检某篇
python3 tools/voice_check.py topics/草稿-xxx.md --baseline voice/基线.json
```

指标分两组：**AI 腔（越低越好）**——公式化过渡 / 抽象大词 / 对仗模板 / 空转过渡；
**人味（可对照）**——第一人称 / 第二人称 / 口语词 / 情绪自嘲 / 破折号 / 省略号 / 括号 OS。

> 注意：**第二人称低于基线不一定是问题**。口语语料的"你"密度（50+/千字）属于口语场景，
> 写文章时不迁移是刻意选择，不是偏差。

## 9. `backup.sh` — 一键备份（内置隐私审计门槛）

```bash
bash tools/backup.sh "改了什么"
```

流程是 **审计 → 提交 → 推送**，顺序不能反：

1. `git add -A`（先暂存，让新增文件也进审计范围）
2. 跑 `privacy_audit.py --history`，**不通过直接退出，不提交也不推送**
3. 有改动就提交，然后推送到**所有已配置的远程**

误报时可用 `bash tools/backup.sh "说明" --no-audit` 跳过，但会打印警告。
**这个逃生口会绕开全部检查，只在你确认过审计结果时用。**

## 10. `privacy_audit.py` — 隐私审计

推送前逐一排查可能泄露本人身份或数据的内容。**仓库是公开的，一次误推不可逆。**

```bash
python3 tools/privacy_audit.py              # 扫 git 跟踪的文件 + git 元数据
python3 tools/privacy_audit.py --all-files  # 连未跟踪文件一起扫
python3 tools/privacy_audit.py --history    # 连全部 git 历史一起扫（慢但彻底）
```

**退出码**：0 = 干净｜1 = 有 CRITICAL/HIGH｜2 = 仅有 MEDIUM｜3 = 自检失败（结果不可信）

**检查面**

| 类别 | 内容 |
|---|---|
| 凭据 | AppSecret / token / 私钥 / `sk-` `ghp_` 等 |
| 本机环境 | 绝对家目录路径（含用户名） |
| 联系方式 | 邮箱、手机号 |
| 账号数据 | 粉丝数、收入、阅读量等运营指标 |
| 个人主页 | 指向个人主页的链接 |
| 私有关键词 | `.privacy-local.txt`（gitignore）里你维护的身份词 |
| **Git 元数据** | **提交作者 / 提交者、提交信息** |

**两层配置，工具本身不含你的任何私人词**

| 文件 | 作用 | 是否进仓库 |
|---|---|---|
| `.privacy-local.txt` | 你的身份词表（品牌名、用户名、真名…） | ❌ gitignore |
| `.privacy-ignore` | 第三方文件忽略清单（只含路径） | ✅ 可提交 |

**逐行豁免**：某行含 `privacy-audit:ok` 就跳过该行的命中，用于已人工确认的误报
（例如第三方许可证里的邮箱）。⚠️ **对 CRITICAL 不生效**——不能让一句注释放行真密钥。

**内置护栏**：中文名文件读不到时**拒绝出报告**（退出码 3）。
这条来自一次真实事故：`git ls-files` 默认转义非 ASCII 文件名，导致中文名文件被静默跳过、审计漏报 17 处。

## 11. `backup_work.sh` — 工作数据备份

稿件、选题存档、风格卡等工作数据**已从 git 排除**，走独立的 rsync 备份。

```bash
bash tools/backup_work.sh              # 增量同步，不删备份里的旧文件
bash tools/backup_work.sh --dry-run    # 只看会同步什么
bash tools/backup_work.sh --mirror     # 严格镜像（本地删了备份也删，有风险）
```

同步清单**不硬编码文件名**，而是问 git"哪些被忽略了"：

```bash
git ls-files --others --ignored --exclude-standard --directory
```

这样加新目录时不用改脚本，也避免把个人文件名写进代码。

目标目录可用 `WORK_BACKUP_DIR` 环境变量改，默认在 iCloud。

## 12. `install_hooks.sh` — 启用 git 勾子

```bash
bash tools/install_hooks.sh
```

把 `core.hooksPath` 指向 `.githooks/`，启用 `pre-push` 勾子。

**为什么需要这一步**

git 出于安全考虑**不跟踪 `.git/hooks/`**（否则别人 clone 一个仓库就能在你机器上执行任意代码）。
因此勾子放在**受版本控制的 `.githooks/`**，再用 `core.hooksPath` 让 git 去那里找。
代价是：`core.hooksPath` 是本机配置，**clone 后每人要跑一次**。

**pre-push 做什么**

推送前跑 `privacy_audit.py --history`，不通过就 `exit 1` 拦住推送。
这是为了兜住 `backup.sh` 管不到的场景——**手动 `git push`**。

| 推送方式 | 谁在拦 |
|---|---|
| `bash tools/backup.sh` | 脚本内置审计 |
| 裸 `git push` | `pre-push` 勾子 |

跳过方式：`git push --no-verify`（会同时跳过两道检查，不推荐）。
