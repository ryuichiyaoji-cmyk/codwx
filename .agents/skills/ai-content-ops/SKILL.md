# 内容生产总纲

**你的角色**：编辑部**调度台 + 规则手册**。本技能提供路由、跨阶段红线与文件地图；**具体执行规则在对应子技能里**。

⚠️ **重要**：说"今天有什么选题"时，本技能与 `ai-topic-scout` **会同时加载**——这是设计如此，不是冲突。
**不要因为加载了本技能就只做路由、不干活。** 正确做法是：用本技能的红线与文件地图，用子技能的执行规则，**把活干完**。

## 一、触发即路由（认意图 → 交子技能）

**收到任何一环节指令，先查这张表，再动手：**

| 用户说 | 走哪个技能 | 交付物 |
|---|---|---|
| 今天有什么选题 / 扫一轮 / 有什么最新动态 | **`ai-topic-scout`** | 5–8 个选题卡（分国内外）+ 搜索验证 + 优先级 |
| 选题X / 写这篇 / 开始写 | **`ai-article-writer`** | 判素材状态 → 六模块稿 + 排版交接单 |
| 起标题 / 优化标题 | **`ai-title-optimizer`** | 8 候选 + 搜索/点击双维打分 |
| 排版 / 准备发布 | **`ai-article-formatter`** | 符合 md2wx 语法的 markdown 稿 |
| 发布草稿箱 / 推送 / 渲染 | **`ai-wechat-publish`** | 渲染 → 封面 → 推草稿箱 |
| 分析数据 / 复盘 | **`ai-data-analyst`** | 指标对比 + 归因（基线空时只记录） |
| 太AI化 / 不像我写的 | **`writing-voice`** | 风格卡更新 |

**一次只走一个环节。** 用户说"今天有什么选题"就只做选题，不要顺手写稿——链条的下一环等他选完再说。

**工作流全景**：
```
今天有什么选题 → 选题卡 → 用户选序号
   → 判素材状态（A 有素材 / B 无素材）
   → 六模块写作 → 附排版交接单
   → 内容层排版 → preflight（退出码必须 0）
   → md2wx 渲染 → 封面 → 推草稿箱 → 用户后台手动发布
```

## 二、四个环节自动串起来的方式

**不用用户重复下指令的只有一件事：把"下一步是什么"讲清楚。**

- 选题交付完 → 结尾必须是「选哪个？回复序号即可」
- 选完题后，**先判素材状态再写**（状态 B 只能出脚本，不许写实测）
- 稿子交付完 → 结尾提示「跑 preflight 过了才能进发布」
- 发布完 → 提醒用户去后台手动点发表 + 更新记忆文件

**不要自动往下跑。** 每一环都要用户确认，因为每环都有他的判断（选哪个题 / 素材够不够 / 风格对不对）。

## 三、接手先读这四份（每次都要）

| 文件 | 作用 |
|---|---|
| `voice/风格卡.md` | **个人文风，硬约束**。写作/改稿前必读；卡里写"不用"的一处都不许出现 |
| `account-status.md` | 账号状态。**数字只能来自这里，不推测**；超 7 天未更新先提醒 |
| `module-log.md` | 小标题与切入顺序历史（同质化去重） |
| `上下文.md` | 体系级决定与依据 + 已知坑（**有疑问先查这里，别重新讨论**） |

## 四、跨阶段红线（全流程适用，一票否决）

- **零编造**：关键数字 2 个独立信源；**官方文件 > 媒体报道 > 社媒帖**（社媒帖只能当线索）
- **禁引用标记** `[reference:n]`｜**禁配图提示**（"此处放图"这类文字）｜**禁序号泄漏**（"国内1、"不许进正文）
- **禁匿名信源**（据说 / 网传 / 业内人士 / 知情人士）
- **禁夸张词**：背叛 / 狂裁 / 炸场 / 出走 / 怒 / 惨 / 秒杀 / 吊打
- **无素材不写实测**：状态 B 必须文末注明「本文未做实测」
- **合规三件套必出**：AI 标识 + 数据来源 + 商业关系
- **账号数据只能来自状态块**

## 六、三条硬规矩

1. **一道流程只归一个技能管**：内容层排版归 `ai-article-formatter`，渲染推送归 `ai-wechat-publish`，不要互相越界
2. **发布前必跑 preflight，贴脚本原始输出**，不用自己打的勾代替
3. **拿不准就先读 `上下文.md`**——里面记了已定的事和依据，避免重复讨论

## 七、维护约定

1. **一处维护**：规则只在本仓库改；改了要同步到你在用的其它 Agent 环境，不要两边各自维护
2. **引用的平台规则都标注日期**，各人拿到的规则版本才一致
3. **改动走 git**，技能与脚本一起评审
