# 公众号排版

**职责边界**：你负责**呈现**，不负责**内容和观点**。发现内容问题时**只标注、不擅自改写**——改写要回 `ai-article-writer`。

**交付物**：一份**符合 md2wx 语法的 markdown 稿**（渲染与推送交给 `ai-wechat-publish`）。

**分工**：本技能只管**内容层**——段落多长、哪里加粗、小标题隔多远、图放几张。**视觉样式（配色/胶囊/卡片）由 md2wx 负责，不在本技能范围内。**

## 一、移动端可读性（硬规则）

公众号 90% 以上读取发生在手机。按 **iPhone 屏宽 ≈ 每行 15–17 个中文字** 估算。

| 规则 | 判据 |
|---|---|
| **单段 ≤ 4 行** | 即一段不超过约 65 字。超过就拆——**这是排版第一大问题** |
| **单段 ≥ 1 行** | 不写"半句话换行"式的碎句 |
| 段落之间空一行 | 不靠缩进，靠空行分节 |
| 连续 3 段以上等长 | 视觉死板 → 把中间一段拆成两句 |
| 全文不能出现超过 4 行的段落 | 发布前必须扫一遍 |

**拆段方法**：按语义拆（一个意思一段），不是按字数硬切。转折词（"但""不过""所以"）通常是天然的段落边界。

## 二、小标题写法

**走 md2wx.py 自动渲染链路**（渲染 → 推草稿箱），所以：

```
## 一、小标题文字
```

- **必须用 `##`** —— md2wx 会把它渲染成冷灰蓝圆角胶囊
- **带中文序号**（一、二、三），长文层级一眼可扫
- ⚠️ **不要用 `▍` 或其它花式符号**：md2wx 不认，会当普通文字原样显示
- 全篇只用 `##` 一种层级，不混用 `###`
- 每 300–500 字出现一个小标题；**两个小标题之间不能超过 600 字**（超过读者会失去位置感）
- 小标题与 `module-log.md` 里的历史写法去重（同质化判定看这个）

## 三、重点标注

**加粗是稀缺资源**，用多了等于没重点。

| 规则 | 判据 |
|---|---|
| 全文加粗**不超过 8%** 的正文文字 | 用 preflight 的 `加粗密度` 项核对 |
| 每次加粗**只包住一个关键词或数字** | 不整句加粗、不整段加粗 |
| 一段内**最多 1 处**加粗 | 2 处以上就失去焦点 |
| 优先加粗**数字与结论词** | 如 `46 分`、`262 万美元`、`不是……而是……` |

**引用块**（编辑器的"引用"样式）只用于两类：
1. 官方原话（带出处的直接引语）
2. 全文金句（结论句）

其余一律普通段落。

## 四、配图

| 位置 | 放什么 |
|---|---|
| 开头（标题下） | 封面延展图或主题图，**放一个即可** |
| 每个小标题之后 | 若该节有数据/对比，放一张图或表格截图 |
| 对比/清单处 | 能用表格就别用文字堆；**3 列以内**，超过 3 列就截图成图 |
| 结尾前 | 可选（引导关注图） |

**密度**：每 **350–500 字**一张图。低于 350 字一张会显得碎，超过 700 字没有图会显得干。

**用 Markdown 图片语法写出**（md2wx 会渲染成带冷灰边框的图）：

```
![AA 榜单截图：46 分与 53 分两行](assets/榜单.png)
```

⚠️ **绝对不要写"此处放图""配图N"这类占位文字** —— 那是本号红线明令禁止的「配图提示」，md2wx 会把它们渲染成正文文字。**有图就写图片语法，没图就整行省略。**

**图注**（可选但推荐）：图下方一行灰字说明来源，格式 `来源：XXX，2026`。

**禁止**：AIGC 生成图当主体配图，尤其是含文字、数据、人脸的图——容易出合理性错误（低价值 AIGC 判定）。

### 用模板生成（推荐，不要每次现写脚本）

```bash
python3 tools/make_figs.py <版式> -t "标题" -s "来源：XXX" -o assets/xxx.png [数据参数]
```

五种版式，统一冷灰科技蓝 **#3D5A80**、1080px 宽，每张自带标题与来源行：

| 版式 | 数据参数 | 适用场景 |
|---|---|---|
| `信息` | `-k "键::值"` | 论文 / 公告 / 报告的基本信息卡 |
| `对照` | `-c "头::副::主体::标签::备注"`（2–4 列） | 两家或三家的方案、路线对比 |
| `清单` | `-i "主::副"`（自动编号） | 案例清单、事故清单、要点罗列 |
| `条目` | `-i "左::主::右"`（不编号） | 法案编号、榜单这类左对齐列表 |
| `柱状` | `-d "标签:值:副标签"` ＋ `--unit %` / `--highlight-below N` | 数字对比，低于阈值自动标橙 |

分隔符：列内字段用 `::`，柱状数据用 `:`（三段为 标签:值:副标签）。

**生成后先看图**，确认没有文字溢出卡片边界、装饰元素没压到标题，再写进稿件。
手工 matplotlib 只在模板表达不了时才用。

## 五、开头与结尾

**开头**（标题下第一屏）必须有：

```
【导语】一句话，≤40 字，说清这篇讲什么、为什么值得看
```

不要用"今天我们来聊聊……"这种报到式开头。

**结尾**固定三块，顺序不能变：

```
## 五、关咱啥事        ← 正文内容，由 ai-article-writer 提供
【配图N】引导关注图（可选）
📌 关注引导一行 + 互动问题一行
## 七、合规声明        ← AI标识 + 数据来源 + 商业关系
```

## 六、分隔与空格

- 分隔符全篇最多用 2 次（章节之间），形式统一为 `— — —`（前后空行）
- 中英文之间加空格：`用 Codex 写` 而不是 `用Codex写`
- 数字与单位之间不加空格：`46分`? → **不加**，写 `46 分` 保持一致（全篇统一即可）
- 不用「！！」「？？」，感叹号全篇 ≤3 个

## 七、发布后需人工做的事（单独输出）

```
□ 标题：确认用 ai-title-optimizer 选定的那一条（公众号标题 ≤64 字）
□ 摘要：在后台手动填一句（不填会自动截开头，常截得很难看）
□ 封面：后台确认已上传（900×383）
□ 话题/合集：在后台编辑器设置（正文里不要写 #标签，微信不认）
□ 原创声明：按平台规则决定是否勾选
□ AI 生成内容标识：确认合规声明块已随正文推送
□ 留言：开启
□ 手机预览一遍：重点看有没有超过 4 行的段落、图片有没有错位
```

**渲染、封面生成、配图上传、curl 推送草稿箱 → 全部走 `ai-wechat-publish`，本技能不做。**

## 八、交付格式

交付一份 **markdown 文件**，按下面的语法写（md2wx 全部支持）：

- 加粗：直接用 `**文字**`（md2wx 渲染成加粗，不需手动处理）
- 小标题：直接用 `## 一、xxx`（md2wx 渲染成胶囊）
- 图片：用 `![图注](本地路径)`（md2wx 渲染 → 推送前自动上传微信素材库并替换为永久 URL）
- 表格：**Markdown 表格可用**（md2wx 支持 `table-layout:fixed`），但手机端**不超过 3 列**，超了就转图
- ⚠️ **多行代码块（三反引号）不要用**：md2wx 不支持，会被当字面文本。要贴多行命令就一行一段连续写

## 自检（交给 preflight）

排版稿写完后跑：

```bash
python3 tools/preflight.py <排版稿>
```

脚本会查**单段超长、加粗密度、小标题间距、配图位数量、分隔符混用**等排版项。
**脚本报警的地方必须改，不许以"读者不会注意"为由放过。**
