# 标题工厂

核心矛盾：推荐流要情绪，搜索流要关键词。解法是 **关键词前置 + 情绪后置**。

## 硬规则（两条规范合并且已消解冲突）

原设计里「16–22 字」与写作规范的「25 字以内」互相打架，统一为：

- **长度 16–25 字**（下限保证信息量，上限保证搜索结果不截断）
- **核心词必须在前 15 字内**——搜索结果只展示前 15 字
- **必须带 Emoji**
- **必须含具体数字，或「实测 / 对比 / 体验」字样**
- 同一个核心词**只出现 1 次**（重复 = 刻意优化，会被判降权）
- **禁止纯情绪标题**：情绪必须挂在一个事实或数字上
- **禁止标题已说完全部内容**：数字要指向**结果**，不要指向**结论**
- **可以给判断，但不能把答案给完**（V6 明确）：判断要指向"为什么"或"怎么办"，
  例如"X 换了条路"可以，"X 换了 A 路所以以后 Y 会消失"不行

**禁止词**：背叛 / 狂裁 / 炸场 / 出走 / 怒 / 惨 / 秒杀 / 吊打

## 两种结构

- **A · 关键词 + 落地价值**：`Suno商用版权新规：3种能用/3种不能用，附合规清单`
- **B · 痛点长尾词 + 解决方案**：`AI音乐总被判侵权？实测5个可商用平台，第3个免费`

## 输出格式

生成 **8 个候选**，每个按「搜索权重」和「点击吸引力」双维打分（各 0–10），给出总分与推荐理由：

| # | 候选标题 | 字数 | 搜索权重 | 点击吸引力 | 是否已说完全部内容 |
|---|---|---|---|---|---|

另附两个特化版本：
- **1 个最稳妥的**（搜索权重最高，适合纯搜索型选题）
- **1 个最强传播的**（情绪钩子最足，适合推荐流型选题）

## 交付前验证

先查 `module-log.md`：**同一篇文章里已经用过的小标题写法，标题不要重复套用**。

把入选标题写进草稿文件后跑：

```bash
python3 tools/preflight.py <稿件文件.md>
```

脚本会硬性检查：字数上限 / 是否含数字或信号词 / 是否带 Emoji。
**「是否已说完全部内容」脚本判不了，逐条说明，不要跳过。**

## 红线

- 标题里的数字必须来自已核实信源，不许为了标题好看编数字
- 不许为了点击率牺牲准确性（例如实测没做就不写"实测"）
