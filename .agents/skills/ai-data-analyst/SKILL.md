# 数据复盘（V7.0）

## 收集什么

发布后 24 小时记录：阅读量 / 完读率 / 新增关注 / 搜一搜占比 / 推荐占比 / 收藏数 / 分享数。
同时记录形态：**实测 / 教程 / 资讯 / 批判**。

**你无法读取公众号后台**，所以数据必须由用户粘贴。用户没给的数据就留空，不要估算。

## 先做账号健康度四查

每次复盘先查这四项，再谈单篇指标：

| # | 查什么 | 看哪里 | 判据 |
|---|---|---|---|
| ① | 账号检测 | 后台“账号检测”页 | 第 5 项“符合内容推荐条件”是否异常 |
| ② | 产出结构 | `account-status.md` + `perf-log.md` | 本流程加工稿 vs 直发稿 |
| ③ | 断更时长 | 最近成稿 / 发布日期 | 恢复期 > 2 天 = 🔴 |
| ④ | 形态配比 | `perf-log.md` 最近 6–8 篇 | 实测 / 教程应占多数；连续 3 篇资讯 / 批判 = 🔴 |

**账号健康优先于单篇优化**。若账号检测异常，先止血，不要先改标题。

## 重点盯两个

**单篇涨粉率** = 新增关注 ÷ 阅读量
**搜一搜占比**

⚠️ 不要搬用外部硬阈值。正确做法：

1. 从 `account-status.md` 的「历史基线」取自己的中位数
2. 与此前数据比**变化方向**，不比外部标准
3. 基线为空时：**只记录，不下结论**，把本次数据写回状态块作为起点

判断逻辑：

- 涨粉率低于自己中位数 → 大概率是文末钩子或自动回复资源没起作用
- 搜一搜占比低于自己中位数 → 大概率是标题核心词没前置，或选的词没有真实需求
- 形态配比异常 → 先调整下周形态，不要只看单篇爆款

## 每周复盘

**本周最高阅读和最低阅读的两篇，差在选题、标题、形态还是钩子？** 给一个明确判断，不要说“都有影响”。

## 闭环（必做）

1. 把 24–48h 数据回填到 `perf-log.md`
2. 把本期结论回填到 `account-status.md`：更新基线、阶段、Top3、账号检测快照
3. 格式是否失衡，会直接影响下轮排产

**不复盘的复盘等于没做。**

## 安全

- 数据表格含收入与粉丝信息，**只在本机分析，不要上传任何第三方服务**
- `account-status.md` 与 `perf-log.md` 已 gitignore，不要提交
