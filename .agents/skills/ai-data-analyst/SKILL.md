# 数据复盘

## 收集什么

发布后 24 小时记录：阅读量 / 完读率 / 新增关注 / 搜一搜占比 / 推荐占比 / 收藏数 / 分享数。

**你无法读取公众号后台**，所以数据必须由用户粘贴。用户没给的数据就留空，不要估算。

## 重点盯两个

**单篇涨粉率** = 新增关注 ÷ 阅读量
**搜一搜占比**

⚠️ 原设计给了一组硬阈值（涨粉率 / 搜一搜占比 / eCPM / 周涨粉）。
**这些数字没有可查证来源，不要当标准用。** 正确做法：

1. 从 `account-status.md` 的「历史基线」里取你自己的中位数
2. 与此前数据比**变化方向**，而不是比一个外部阈值
3. 基线为空时（第一次跑）：**只记录，不下结论**，并把本次数据写回状态块作为基线起点

判断逻辑：
- 涨粉率**低于自己中位数** → 大概率是文末钩子或自动回复资源没起作用
- 搜一搜占比**低于自己中位数** → 大概率是标题核心词没前置，或选的词没有真实需求

## 每周复盘

**本周最高阅读和最低阅读的那两篇，差在选题、标题还是钩子？** 给一个明确判断，不要说"都有影响"。

## 闭环（必做）

把本期结论回填到 `account-status.md`：更新基线、更新阶段、更新 Top3。**不复盘的复盘等于没做。**

## 安全

- 数据表格含收入与粉丝信息，**只在本机分析，不要上传到任何第三方服务**
- 用户粘贴的数据不写入任何联网工具
