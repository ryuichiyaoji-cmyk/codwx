# 内容生产技能套件

一套把**公众号内容生产全流程**（选题 → 写作 → 标题 → 排版 → 发布 → 复盘）固化成
**Agent Skill + 可执行脚本** 的系统。机械环节交给脚本，判断力留给模型和人。

> 起源：一个 AI 垂类公众号，曾因"拼盘资讯 / 纯转述 / 标题已说完"被判**低创作度降权**。
> 这套规则和工具是为**爬出降权**而设计的——每一条约束都对应踩过的坑。

---

## 一、它解决什么问题

大部分 AI 写稿流程的问题不是"写不出来"，而是：

| 问题 | 这套系统怎么解 |
|---|---|
| 写出来像 AI 通稿，被判低创作度 | 提炼**个人风格卡**（从真实语料盲测得出），写成硬约束并机器校验 |
| 篇篇结构雷同，触发同质化判定 | 记录**小标题与切入顺序历史**，新稿自动查重 |
| 选题靠感觉，写了没人搜 | **三层信源扫描 + 搜索需求实测**，选题带评分与长尾词 |
| 数字编造、信源不实 | **零编造红线**：关键数字需 2 个独立信源，官方文件优先 |
| 发布流程繁琐且易漏步 | **一条命令**：渲染 → 封面 → 上传素材 → 推草稿箱 → 回查 → 写日志 |
| 改排版时误改文字 | **字符级核验**：渲染前后中文/字母数字/emoji 三段序列必须完全一致 |

## 二、全流程

```
① 选题        python3 tools/topic_scan.py --hours 48 --top 12
              抓 11 个信源 RSS → AI 过滤 → 自动聚类 → 搜索验证 → 归档
              ↓ 输出候选簇 + 每个选题的搜索需求分
② 开稿前      python3 tools/draft_kit.py brief
              一屏读完：风格卡硬约束 / 账号状态新鲜度 / 去重清单 / 规格
              ↓
③ 写作        六模块结构（功能固定、表达每篇不同）+ 合规三件套
              ↓
④ 完稿体检    python3 tools/draft_kit.py check topics/xx.md
              preflight（27 项）+ 文风体检，合并成一屏
              ↓
⑤ 配图        python3 tools/make_figs.py 对照 -t "标题" -o assets/a.png
              信息 / 对照 / 清单 / 条目 / 柱状 五类模板
              ↓
⑥ 排版        ai-article-formatter 技能：段落长度 / 加粗密度 / 配图节奏
              ↓
⑦ 发布        python3 tools/wx_publish.py formatted/xx-排版稿.md
              ↓ 草稿箱（用户在后台手动点发布）
⑧ 备份        bash tools/backup.sh "说明"
```

## 三、快速开始

```bash
git clone <本仓库地址> && cd <仓库名>

# 1) 看看有哪些技能与工具
cat docs/技能手册.md
cat docs/工具手册.md

# 2) 跑一次选题扫描（需联网）
python3 tools/topic_scan.py --hours 48 --top 12

# 3) 开稿前读情报包（离线）
python3 tools/draft_kit.py brief

# 4) 稿件体检（离线）
python3 tools/draft_kit.py check topics/你的稿子.md
```

**要接到自己的账号**：见 [`docs/接入指南.md`](docs/接入指南.md)——
风格卡、账号状态块、微信凭据三处换成你自己的即可。

## 四、八个技能（`.agents/skills/`）

| 技能 | 触发词 | 交付物 |
|---|---|---|
| **`ai-content-ops`** | 任一环节指令 | 认意图 → 路由子技能 + 跨阶段红线 + 工具地图 |
| `ai-topic-scout` | 今天有什么选题 | 5–8 个选题卡（分国内外）+ 搜索验证 + 优先级表 |
| `ai-article-writer` | 写这篇 / 选题X | 判素材状态 → 六模块稿 + 排版交接单 |
| `ai-title-optimizer` | 起标题 | 8 候选 + 搜索/点击双维打分 |
| `ai-article-formatter` | 排版 | 符合 md2wx 语法的 markdown 稿 |
| `ai-wechat-publish` | 发布草稿箱 | 渲染 → 封面 → 推草稿箱 |
| `ai-data-analyst` | 分析数据 / 复盘 | 指标对比 + 归因（基线为空时只记录） |
| `writing-voice` | 太AI化 / 不像我写的 | 从真实语料提取风格卡 |

`ai-content-ops` 是**统一入口**：说出任一环节，它自动路由，并带上跨阶段红线。

## 五、九个工具（`tools/`）

| 脚本 | 一句话 |
|---|---|
| `topic_scan.py` | 选题扫描一键跑：抓源 → 自动聚类 → 搜索验证 → 归档 |
| `scan_feeds.py` | 11 个信源 RSS 抓取 + AI 关键词过滤（被 topic_scan 复用） |
| `draft_kit.py` | 写稿提速：`brief` 情报包 / `check` 完稿体检 / `handoff` 交接单骨架 |
| `make_figs.py` | 配图模板：信息 / 对照 / 清单 / 条目 / 柱状，统一视觉 |
| `wx_publish.py` | 一键发布：渲染 → 封面 → 上传素材 → 推草稿箱 → 回查 → 写日志 |
| `preflight.py` | 发布前自检 **27 项**（禁用词/结构/合规/排版/风格卡），退出码 0 才可发 |
| `search_demand.py` | 搜索需求验证：Bing/Google/百度 建议接口 → 打分 + 长尾词 |
| `voice_check.py` | 文风体检：对照个人语料基线，查 AI 腔与人味指标 |
| `backup.sh` | 一键备份：提交改动 → 推送到所有远程 |

详细参数与示例输出见 [`docs/工具手册.md`](docs/工具手册.md)。

## 六、四条硬约束（一票否决）

1. **低创作度四条优先排除**：同质化 / 抄袭搬运 / 低信息量 / 低价值 AIGC
2. **每个选题必须回答「这件事改变了什么旧规则？」**——答不出来就是纯资讯
3. **无素材不写实测**：默认分析型，禁止亲历式描述；文末必须声明「本文未做实测」
4. **交付前跑脚本、贴原始输出**——不用人打的勾代替机器判定

配套的其他红线：零编造（关键数字 2 个独立信源，官方文件 > 媒体报道）｜禁匿名信源｜
禁引用标记｜禁配图提示文字｜禁草稿序号泄漏｜合规三件套必出（AI 标识 + 数据来源 + 商业关系）。

## 七、环境要求

| 项 | 要求 |
|---|---|
| Python | 3.10+（`preflight` / `draft_kit` / `topic_scan` 等纯离线脚本） |
| 第三方库 | `matplotlib`、`Pillow`（仅配图与封面用） |
| 中文字体 | macOS：`STHeiti Medium.ttc` + `Hiragino Sans GB.ttc`；其它平台改 `tools/make_figs.py` 顶部的字体路径 |
| 微信发布 | `WX_APPID` / `WX_APPSECRET` 放 `~/.workbuddy/.env`（**不要进仓库**） |
| 渲染引擎 | 微信公众号 HTML 渲染可选；`wx_publish.py` 默认调用本机 md2wx，纯文本流程不依赖它 |

**只跑离线部分**（选题评估、稿件体检、配图、文风）不需要任何凭据。

## 八、隐私与凭据

- `account-status.md`（粉丝数、收入等）**已 gitignore**，不进仓库
